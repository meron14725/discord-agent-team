# ADR 0008: エージェント実行を上限と承認ゲートで制御する

## Status

Accepted.

## Decision

一つの案件で使うモデル実行予算を最大30回とする。その内訳として、内部相談は案件全体で最大15回かつ同一の相談論点で最大5回、実装計画の修正は最大3回とする。上限に達した案件は自動継続せず、実行内訳、未解決事項、推奨対応をオーナーへ提示する。当面はCodexサブスクリプションを利用し、金額による日次上限は設けない。

案件固有の相談記録は要件Issueのコメントへ残す。複数案件で再利用する判断または独立して追跡すべき作業だけ関連Issueへ分ける。相談記録には、安定した論点ID、相談回数、質問、判断材料、選択肢、推奨案、採用結果、未解決事項、参照資料を含める。制御層は論点IDごとの回数を一つの更新として記録し、論点名の変更による上限回避を許可しない。非公開の思考過程は保存しない。

独立した読み取り調査、相談、レビューは通常workerで同時に最大4件実行できる。Issue本文、実装計画、同じリポジトリのコードを変更する処理は、対象ごとのロックで直列化する。別リポジトリの案件は並列実行できる。SREの特権操作は同時実行数1の専用workerへ分離する。

役割は役割台帳へ登録し、統括が必要な2〜4役を選ぶ。台帳には責務、扱える依頼、利用可能なツール、禁止操作、入出力形式、相談可能な相手、並列区分を含める。専門役間の依頼は型付きイベントとして制御層が配送し、DiscordのBot投稿そのものを命令として再解釈しない。

Discordでは受付を5秒以内に返し、空きworkerがあれば30秒以内に処理を開始する。実行中は案件状態メッセージを2分ごとに更新する。10分間更新がなければ滞留と判定して一度だけ再実行し、再び失敗したらSREへ渡す。

必要なBotまたはworkerが停止している場合は最大5分待ち、最大3回まで接続を試す。同等の能力を持ち、より強い権限を必要としない代替役が役割台帳に登録されている場合だけ、代替履歴を話題スレッドへ表示して振り替える。オーナー承認とSRE特権操作は代替しない。代替できなければ案件を停止してSREへ渡し、オーナーへ通知する。

GitHubへの保存または承認版の照合に失敗した処理は進行を止め、段階的に待ち時間を増やして最大3回再試行する。解決しなければSREへ渡し、GitHub以外を一時的な正本にはしない。説明成果物の生成は最大2回再試行し、解決しない場合に限り、文章による説明とオーナーの明示承認を代替手段として認める。

PRは、受入条件ごとの検証結果、必須CIの成功、重大なレビュー指摘の解消、最新コミットに対するオーナー承認がそろった場合だけ完了できる。承認後にコミットが変わった場合は承認を失効させる。マージの最終判断はオーナーが行い、その承認後にBotがマージ操作を実行できる。

現在、要件、計画、マージを承認できるのはDiscordユーザーID `312561681387487232` だけとする。Botと他ユーザーの発言は承認として扱わない。承認は対象成果物のハッシュと再利用できない確認IDへ結び付ける。将来承認者を増やす場合は、オーナーが工程別の許可リストを変更する。

オーナーは案件をいつでも中止できる。実行中と待機中のジョブを止め、Issueを閉じるが、Issue、ブランチ、成果物、監査記録は自動削除しない。再開は新しい案件実行として扱い、現在のIssue本文に対する要件承認からやり直す。

## Consequences

自律実行の暴走、古い承認による実装、同一リポジトリの競合を制御できる。長い案件は上限到達時にオーナー判断が必要になり、外部サービス障害中は処理が停止する。GitHubを唯一の要件正本として保つため、この停止を許容する。
