# ADR 0005: GitHub Issueを開発要件の正本にする

## Status

Accepted. ADR 0001の「新規リポジトリとIssueは仕様承認後に作る」という時期の決定を、この開発フローについて置き換える。

## Decision

正式な開発依頼では、上流がプロダクト意図を整理した時点で、既存の対象リポジトリまたは新しい非公開案件リポジトリへ要件Issueを作る。Issue本文を現在有効な開発要件の正本とし、要件定義中は上流が更新する。コメントは質問、回答、判断理由、変更履歴を残す場所とし、現在の要件とは扱わない。

オーナー承認は、Issue番号、本文ハッシュ、更新識別情報、承認者を固定する。承認後に本文が変わった場合は、要件承認、計画承認、未完了の実装を失効させ、上流の再確認へ戻す。Botによる更新は直前に読んだ版との一致を検査し、人または別処理による変更を上書きしない。

要件Issueには、プロダクト意図、対象ユーザー、対象範囲と対象外、機能要件、異常系と権限、非機能要件、受入条件、制約、未解決事項、判断履歴を記載する。重要な未解決事項がなく、受入条件がテスト可能になった時点を要件定義完了とする。完成後にIssue全体の説明成果物を生成し、オーナーが理解した特定版だけを承認できる。

## Consequences

人間と全エージェントが同じIssueを参照できる一方、放棄された案件リポジトリとIssueが残る可能性がある。削除せず、closeまたはarchiveで履歴を保持する。DBは要件本文の別正本を持たず、版、ハッシュ、承認、実行状態を監査記録として保持する。新しい正式開発依頼からこの方式を適用し、進行中案件は自動移行しない。
