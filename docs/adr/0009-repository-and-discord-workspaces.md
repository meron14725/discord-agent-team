# ADR 0009: リポジトリとDiscordを案件の作業空間として対応付ける

## Status

Accepted.

## Decision

リポジトリごとに `project-<リポジトリ名>` Discordチャンネルを置く。各案件について、チャンネル内に一つの案件状態メッセージを作り、状態、要件Issue、実装計画、PR、話題別スレッドへの索引として更新する。進捗ごとに同内容の通知を追加しない。

案件内では話題ごとに公開スレッドを作る。担当エージェントは該当スレッドで会話し、その話題でオーナー確認が必要になった場合は同じスレッドでメンションする。権限操作と実行基盤の監査記録は、話題スレッドではなくSRE監査チャンネルへ送る。

専門役間で仕事を渡す場合、依頼元Botは依頼先Botをメンションし、目的、依頼内容、期待する成果物、関連Issue、話題IDを該当する話題スレッドへ投稿する。依頼先Botは依頼元Botをメンションし、受付、必要な質問、結果または失敗を同じスレッドへ返す。これらは制御層の型付き依頼を人が読める形へ変換した会話ログであり、Bot間のDiscordメッセージを直接実行契機にはしない。

Bot同士の会話ログは自動削除しない。解決した話題スレッドは24時間後に自動アーカイブし、必要になれば再開する。判断結果は要件Issueのコメントへ要約し、案件成果物索引からIssueコメントとDiscordスレッドを参照できるようにする。DBには型付き依頼のID、関係者、状態、内容ハッシュ、DiscordメッセージIDを保持する。

統括は自然文の意図から、コード、設定、依存関係、インフラ、DiscordまたはGitHub構成の作成、変更、修正、削除を正式開発依頼として判定する。雑談、説明、読み取り調査は通常会話として扱う。判定が曖昧なら一つの短い質問で確認する。リポジトリ用チャンネルでは対象リポジトリを自動決定し、それ以外のチャンネルで対象が不明なら既存リポジトリの指定または新規作成をオーナーへ確認する。

新規リポジトリと対応するDiscordチャンネルの準備はSREの管轄とする。リポジトリはGitHubアカウント `meron14725` 配下に非公開で作成し、公開化にはオーナーの明示承認を必要とする。SREは既定ブランチ保護、必須CI、直接push禁止、Squash merge、Botの必要最小限権限を設定し、変更前検査、監査記録、変更後検証を行う。

要件承認後に既定ブランチの基準コミットを固定し、`agent/issue-<番号>-<短い名前>` ブランチを作る。実装計画とコードは同じ案件ブランチへ保存し、実装開始時にDraft PRを作る。リポジトリ固有の規則がなければSquash mergeを使い、マージ後に案件ブランチを削除する。

## Consequences

オーナーとエージェントはリポジトリ単位で案件を見つけ、案件状態メッセージから各論点をたどれる。話題ごとの会話は分離される一方、案件状態メッセージと成果物索引を更新しなければ情報が散らばるため、制御層が両方の更新を担う。SREにはリポジトリとDiscordを設定する権限が必要だが、公開化など影響の大きい変更は承認ゲートを通る。
